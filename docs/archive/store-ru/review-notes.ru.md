# Поля Chrome Web Store

Версия: 1.19.1 · Сверено с исходниками 25 октября 2026 года.

## Назначение (Single purpose)

Space помогает организовывать сайты и открытые вкладки и быстро переходить к нужной странице через боковую панель и поиск. Сохранённые сайты группируются в любимое и пространства; связанные настройки и резервные копии обслуживают эту же задачу.

## Обоснования разрешений

| Разрешение | Текст для поля кабинета |
|---|---|
| sidePanel | Используется для встроенного режима боковой панели Chrome. В этом режиме Chrome выделяет место под интерфейс и изменяет ширину области сайта. |
| storage | Локально хранит сайты, их порядок, пространства, настройки и снимок перед импортом. Сессионное хранилище содержит связи с открытыми вкладками и состояние панели. Без него организация сайтов не сохраняется между открытиями панели. |
| tabs | Читает URL, названия и идентификаторы открытых вкладок для списка панели, поиска совпадений и переключения на существующую вкладку. Создаёт, активирует и закрывает вкладки по действиям пользователя. История посещений не запрашивается. |
| scripting | Загружает поставляемые в ZIP локальные скрипты плавающей панели и поиска на обычные страницы и обращается к audio/video и Media Session для плеера панели. Удалённый исполняемый код не загружается. |
| favicon | Показывает настоящие значки сохранённых сайтов и выбранной поисковой системы через встроенный endpoint Chrome. |
| http://*/* и https://*/* | Плавающая панель, кнопка её открытия, поиск и управление воспроизведением должны работать на открываемых пользователем HTTP(S)-сайтах. Поэтому ограничение одним заранее заданным доменом не покрывает назначение. На служебные страницы Chrome скрипты не внедряются; Chrome Web Store исключён из декларативных content scripts. |

## Удалённый код

Расширение не использует удалённый JavaScript, eval, WebAssembly или загружаемые исполняемые модули. Все исполняемые файлы входят в ZIP. Открытие поисковых результатов и пользовательских ссылок — обычная навигация, а не загрузка кода в расширение.

## Данные для Privacy practices

На форме кабинета нужно раскрыть фактическую обработку данных, включая локальную. Источник: [официальный FAQ, пункты 2–7](https://developer.chrome.com/docs/webstore/program-policies/user-data-faq).

Факты для сопоставления с текущими категориями формы:

- Названия/URL открытых вкладок и окон читаются локально для списка, совпадений и переключения. Они не отправляются разработчику; это не доступ к полной истории браузера.
- Названия/URL сохранённых сайтов, пространства и настройки хранятся локально.
- Ввод в строку Space используется локально для совпадений; интернет-поиск отправляет запрос выбранному провайдеру только после явного действия.
- Плеер читает название медиаматериала, исполнителя и состояние/команды воспроизведения на странице. Не записывает звук и видео.
- Выбранный пользователем файл копии читается и проверяется локально. Экспорт скачивает данные в JSON. Снимок перед последним импортом хранится локально для возврата.
- В коде нет передачи данных разработчику, аналитики, рекламы, SDK слежения, чтения паролей, cookies, платежей или регистрации.

Не заявляйте «расширение не обрабатывает никаких данных»: обработка открытых вкладок и сохранённых сайтов есть. Декларации формы и публичная политика должны соответствовать этим фактам. Публичный URL политики указывает на размещённую вами страницу из `privacy/`, а не на локальный путь.

## Сценарий для проверки

1. Открыть обычный сайт и панель значком расширения. Сохранить сайт в любимое и создать пространство.
2. Перетащить сохранённый сайт в пространство; убедиться, что вкладка остаётся открытой.
3. Нажать ⌘K на Mac или Alt+K на Windows/Linux; найти сохранённый/открытый сайт. Стрелки/Tab и Enter выбирают результат. Enter в поле запускает интернет-поиск или открывает HTTP(S)-адрес в новой вкладке.
4. В настройках сменить тему и режим панели; фактические горячие клавиши можно увидеть и переназначить в секции «Клавиатура».
5. Меню панели → «Резервная копия»: скачать JSON, выбрать его обратно, проверить предпросмотр и подтвердить замену. Открытые вкладки остаются; предыдущие данные доступны для восстановления.
6. При воспроизведении на поддерживаемом сайте проверить доступные кнопки плеера. Поддержка команд зависит от сайта.

Тестовый аккаунт и пароль не требуются.
